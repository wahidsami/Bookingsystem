# دليل قسم المواعيد في لوحة تحكم التاجر

هذا المستند يشرح قسم المواعيد في Refah كما هو موجود في الكود الفعلي. يغطي شاشات التاجر، النوافذ الجانبية، النماذج، قواعد العمل، نموذج الحالة والدفع، والتكامل مع تطبيق العميل وتطبيق الموظف، إضافة إلى قائمة الـ endpoints المرتبطة.

## 1. الهدف

قسم المواعيد هو مركز التشغيل الأساسي للحجوزات داخل Refah.

يسمح لفريق التاجر بما يلي:

1. عرض المواعيد في قائمة أو تقويم أو لوحة يومية.
2. إنشاء موعد لعميل موجود أو عميل جديد أو ضيف أو حجز جماعي.
3. مراجعة تفاصيل الموعد، العميل، السجل الزمني، الملاحظات، المدفوعات، والمراجعات.
4. إعادة الجدولة، إعادة التعيين، تغيير الحالة، تحصيل الدفع، وتحصيل المتبقي أو الاسترداد.
5. إدارة الفواصل الزمنية وتوفر الموظفين.
6. المزامنة مع تطبيق العميل وتطبيق الموظف عبر الإشعارات والحالة المشتركة.

### 3.2 حالات الموعد

1. `pending`
2. `confirmed`
3. `checked_in`
4. `in_service`
5. `completed`
6. `cancelled`
7. `no_show`

المعنى:

1. `pending` = الموعد موجود لكنه غير مؤكد بعد.
2. `confirmed` = الموعد مؤكد وجاهز.
3. `checked_in` = العميل وصل.
4. `in_service` = الخدمة بدأت.
5. `completed` = الخدمة انتهت.
6. `cancelled` = الموعد ملغي.
7. `no_show` = العميل لم يحضر.

### 3.3 حالات الدفع

1. `pending`
2. `deposit_paid`
3. `fully_paid`
4. `paid`
5. `refunded`
6. `partially_refunded`

المعنى:

1. `pending` = لا يوجد دفع.
2. `deposit_paid` = تم دفع العربون أو رسوم الحجز.
3. `fully_paid` = تم السداد بالكامل.
4. `paid` = حالة نجاح قديمة أو موحدة.
5. `refunded` = تم الاسترداد بالكامل.
6. `partially_refunded` = استرداد جزئي.

التوصية للعرض:

1. `pending` -> غير مؤكد / غير مدفوع
2. `deposit_paid` -> مدفوع عربون / 50%
3. `fully_paid` -> مدفوع
4. `paid` -> مدفوع
5. `refunded` -> مسترد
6. `partially_refunded` -> مسترد جزئياً

## 7. قواعد العمل

### 7.1 الإنشاء

1. يمكن إنشاء الموعد لعميل موجود.
2. يمكن إنشاء الموعد لعميل جديد.
3. يمكن إنشاء موعد ضيف.
4. يمكن تجميع عدة خدمات.
5. يمكن تعيين الموظف يدوياً أو تلقائياً.
6. يتم حفظ الموظف المطلوب عند اختيار العميل له.
7. طريقة الدفع جزء من الطلب.
8. `notifyCustomer` افتراضياً = true.

### 7.2 قيود الوقت

1. لا يجب عرض أوقات سابقة في نفس اليوم.
2. لا يجب إضافة موعد إلى السلة إذا كان قبل أقل من ساعة من الوقت الحالي في تطبيق العميل.
3. تُستخدم مقارنة التاريخ المحلي لتقليل مشاكل المنطقة الزمنية.

### 7.3 تغيير الحالة

1. التغيير السريع للحالة مقيد بالحالة الحالية.
2. `completed` يتطلب أن يكون الموعد مدفوعاً حسب القاعدة.
3. `checked_in` تعني وصول العميل.
4. `cancelled` و `no_show` حالات نهائية.

### 7.4 الدفع

1. العربون = `deposit_paid`.
2. الدفع الكامل = `fully_paid` أو `paid`.
3. تحصيل المتبقي مدعوم.
4. الاسترداد مدعوم.
5. الدفع يمكن تقسيمه على عدة طرق.
6. المحفظة يمكن استخدامها إن كانت مفعلة.

### 7.5 التعيين

1. الموظف الذي يختاره العميل يُحفظ في `requestedStaffId`.
2. يمكن إعادة التعيين من التاجر.
3. يمكن إعادة التعيين مع إعادة الجدولة في عملية واحدة.
4. يمكن السحب والإفلات بين أعمدة الموظفين.

### 7.6 التأثير على التطبيقات الأخرى

تطبيق العميل:

1. يستقبل إشعارات الحجز.
2. يرى دعوات الموعد.
3. يمكنه القبول أو الرفض.
4. يرى سجل المواعيد.

تطبيق الموظف:

1. يستقبل إشعارات التعيين أو التغيير.
2. يرى الموعد في الجدول.
3. يمكنه تحديث الحالة.

## 10. الخلاصة

قسم المواعيد هو مركز التشغيل الكامل للجدولة والدفع والتعيين والتواصل بين التاجر والعميل والموظف.

إذا أردت تعديل القسم لاحقاً، فالتسلسل الصحيح هو:

1. صفحة المواعيد الرئيسية هي مساحة التشغيل.
2. نافذة الإنشاء هي نموذج الحجز الأساسي.
3. نافذة التفاصيل هي لوحة الإدارة والتحصيل.
4. التقويم هو العرض البصري الزمني.
5. تطبيق العميل والموظف يجب أن يبقيا متزامنين مع أي تغيير.
