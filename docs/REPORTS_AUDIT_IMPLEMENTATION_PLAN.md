# Reports Audit + Implementation Plan

## 1) Audit Summary (Current State)

### A. Accuracy risks found (high priority)

1. Mixed data sources between summary and full report
- `reports/summary` uses `tenantReportsController.getDashboardSummary` (appointments-focused logic).
- `reports/full` "overview" uses `tenantFinancialController.getFinancialOverview` (appointments + orders with financial columns).
- Result: the "overview numbers" can differ between dashboard reports page and generated report preview for the same date range.

2. Inconsistent appointment filters across report endpoints
- Some queries include tenant scope via `service.tenantId`/`staff.tenantId`, others rely on joins with `required: true`, others check direct `tenantId`.
- Result: edge cases may include/exclude rows differently (especially older rows with nullable tenant linkage).

3. Revenue logic is not unified
- Some endpoints sum `price`, others use `rawPrice + tax + fees`, others `tenantRevenue`.
- Payment status handling is inconsistent between endpoints.
- Result: totals can be mathematically correct in isolation but inconsistent between sections.

4. Generated report preview is browser-print only
- Current "PDF" is `window.print()` from HTML preview.
- No deterministic branded PDF generator pipeline, no locked layout, no guaranteed rendering parity.

### B. UX gaps found (medium priority)

1. Generate report page layout is narrow and basic
- No clear "back" navigation pattern like other editor pages.
- Boxes do not fully use page width on large screens.

2. Preview page is utility-first, not presentation-first
- Good for internal review but not ideal as final customer-facing printable report.

### C. Branding/identity gaps (medium priority)

1. Report header lacks formal cover page
- No Refah + tenant logos cover page.
- No standardized metadata block (report id, tenant, period, generated by, generation timestamp, timezone).

## 2) Target End State

1. One financial truth model for all report endpoints.
2. Generate page redesigned with full-width professional layout and explicit back button.
3. Proper PDF export endpoint that returns a branded PDF file with:
- Cover page (Refah logo + tenant logo + report title/period).
- Consistent typography/spacing across pages.
- Repeatable output independent of browser print behavior.
4. Clear reconciliation rules across statuses:
- booking status, payment status, tenant net revenue, platform fees, staff commission.

## 3) Implementation Plan (Phased)

## Phase 1: Financial Canonicalization (Backend)

### Scope
- Create a shared report metrics service:
  - `server/src/services/tenantReportMetricsService.js`
- Service responsibilities:
  - Single date-range normalization helper.
  - Single tenant scoping helper.
  - Canonical metric calculators for:
    - gross revenue
    - paid revenue
    - pending revenue
    - tenant net revenue
    - platform fees
    - staff commission
    - booking/order counts by status

### Refactor targets
- `server/src/controllers/tenantReportsController.js`
- `server/src/controllers/tenantFinancialController.js`

### Rule decisions (to lock)
- Use one status map for "counted bookings/orders".
- Use one payment map for "paid/pending/partial".
- Use one source of truth columns for amounts (`price`, `tenantRevenue`, `platformFee`, `employeeCommission`) with fallback rules.

### Deliverables
- Summary and full report overview return identical totals for same range.
- All section endpoints consume shared calculation helpers.

## Phase 2: Generate Report Page UX Redesign (Tenant)

### Scope
- Redesign `tenant/src/app/[locale]/dashboard/reports/generate/page.tsx`

### UX changes
- Add back button (top left/right based on locale) to reports main page.
- Full-width responsive card grid (date range + section selection + metadata).
- Better distribution:
  - date range block
  - sections block (2-3 columns desktop)
  - report metadata block (title, notes)
  - action bar pinned/clear

### Deliverables
- Visual parity with modern dashboard pages.
- Cleaner layout and easier report setup.

## Phase 3: Branded PDF Export (Server + Tenant)

### Scope
- Add server PDF endpoint:
  - `GET /api/v1/tenant/reports/pdf?...`
- Add PDF renderer service:
  - `server/src/services/tenantReportPdfService.js`

### PDF requirements
- Cover page:
  - Refah logo
  - tenant logo
  - tenant name
  - report title
  - date range
  - generated timestamp
- Body pages:
  - sections selected in generate form
  - consistent table styles
  - page number/footer

### Technical approach
- Preferred: server-side HTML-to-PDF with Playwright.
- Alternative: pdfmake if we want pure programmatic PDF.

### Tenant integration
- In preview/generate page:
  - `Download PDF` button calls new endpoint.
  - Keep `Print` as secondary fallback.

## Phase 4: Validation + Reconciliation Suite

### Scope
- Add internal QA scripts + test checklist to verify data consistency:
  - summary vs full overview
  - daily sums vs overview totals
  - service totals vs appointment totals
  - employee totals vs commission totals

### Deliverables
- SQL-based reconciliation checklist document.
- Postman/endpoint sanity checklist for release.

## 4) Data Contracts (Proposed)

1. `reports/summary` and `reports/full` overview return same shape and same numbers.
2. All monetary values returned as numeric (not string).
3. Include `currency: "SAR"` and `timezone` metadata in responses for reporting.

## 5) Migration / DB Impact

No mandatory schema migration for phase 1-3 if existing columns are stable.

Optional future optimization:
- add reporting indexes for heavy date-range queries.
- add materialized daily aggregates for large tenants.

## 6) Rollout Order

1. Phase 1 (backend truth model)
2. Phase 2 (generate page UX)
3. Phase 3 (PDF service + download button)
4. Phase 4 (validation suite + QA signoff)

## 7) Acceptance Criteria

1. For same date range, numbers match between:
- Reports dashboard cards
- Generated report preview overview
- Downloaded PDF overview

2. Generate page has:
- back button
- full-width balanced layout
- clear CTA hierarchy

3. PDF includes:
- cover page with Refah + tenant logos
- professional styling
- complete selected sections

4. QA reconciliation passes on staging tenant data.
